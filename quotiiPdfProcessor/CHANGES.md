# quotiiPdfProcessor — Dead-Code Removal + arq Worker Refactor

Refactor of 2026-08-06: the processor is now **Cloud-indexing only** (`/index-pdf`, `/retry-index`). All quote-extraction/LLM surface and the legacy `/process-pdf` pipeline were removed, and the in-process `ThreadPoolExecutor` was replaced with an **arq (Redis) queue + standalone worker process**.

Verified against the live consumers: the mobile app (`quotii/`) uploads only via Backend `POST /index` (→ `/index-pdf`); the upload tab is a dummy stub. The Backend calls `/index-pdf`, `/retry-index` (GraphQL `retryCloudIndex`), and `/process-pdf` — but nothing in the app calls the legacy upload route, so `/process-pdf` and its quote extraction are producer-dead end-to-end.

## What was removed (dead code)

- `services/llm/` — whole module: `llmQuoteExtractor.py` (Gemini/OpenAI/Claude quote extraction), `llmQueryHandler.py` (`/ask-quote`), `RagHelper.py`, `spellingCorrector.py`
- `services/pdf/pdfExtractor.py` (legacy quote-pipeline extract) + `generatePdfThumbnail.py`
- `services/infra/AwsUtil.py` (S3 thumbnail upload — also contained the hardcoded-key fallback landmine; gone now)
- `services/domain/textUtil.py`, `services/domain/dataTypes.py` (only the deleted quote path used them)
- Endpoints: `/process-pdf`, `/ask-quote`, `/test-llm` + `process_and_extract_quotes`
- Tests: `test_llm_quote_extractor.py`, `test_llm_query_handler.py`
- Deps: `google-generativeai`, `openai`, `anthropic`, `langchain`, `qdrant-client`, `flask`, `Flask-PyMongo`, `PyPDF2`, `pdf2image`, `Pillow`, `tqdm`, `typing_extensions`

## What was added

- `worker.py` — arq worker (separate process): consumes `cloud_index_job`, `max_jobs=2`, `job_timeout=1800s`, `keep_result=0`. Run with `python worker.py`.
- `services/queue.py` — lazy Redis pool (`REDIS_URL`, default `redis://localhost:6379`) + `enqueue_cloud_index_job(user_id, job_id)`
- `services/indexing/cloud_indexing.py::cloud_index_job(ctx, user_id, job_id)` — arq task that wires production Mongo/R2 (`ctx` is the arq job context, first positional arg by arq convention)
- `README`-worthy run commands (below)

## What changed

- `app.py` — only `/index-pdf` + `/retry-index`. Both enqueue via arq instead of `ThreadPoolExecutor`. If enqueue fails (Redis down), the book is marked `indexStatus: failed` so it is never stuck in `queued`.
- `services/infra/db.py` — Flask-PyMongo + Qdrant removed; plain lazy `pymongo.MongoClient`, db name from `MONGO_URI` path
- `requirements.txt` — pruned to what runs; added `arq`, pinned `redis<5.2` (redis 5.2+ hard-imports `jwt`, breaking arq import)
- `tests/test_app.py` — rewritten for the two remaining endpoints (validation, 202s, enqueue kwargs, Redis-down failure path)
- `tests/test_cloud_indexing.py` — added arq seam tests (stable job name, ctx-first wiring)
- `.env.example` — dropped QDRANT_* (dead), added `REDIS_URL`

## How to run

```bash
# API (port 8000) — as before
./.venv/bin/python run.py

# Worker — NEW separate process (needs Redis + same MONGO_URI/R2_* env)
./.venv/bin/python worker.py
```

Tests: `PYTHONPATH= ./.venv/bin/python -m pytest tests/ -q`

## Knock-on effects to be aware of

- **Backend `/upload` route** (`quotiiBackend/src/index.ts:240`) still POSTs to `/process-pdf` → will get a 404/error if ever hit. Nothing in the app calls it today. Backend untouched per instruction; route cleanup is a backend-side follow-up.
- **Favorites screen** in the app still reads the Mongo `quotes` collection (legacy data stays visible), but no new quotes will be produced.
- **Thumbnails** were only generated by the removed `/process-pdf` path; cloud indexing never set `thumbnailKey` — legacy behavior unchanged.
- `.env` is deleted from disk (staged earlier); recreate from `.env.example` before running locally.
